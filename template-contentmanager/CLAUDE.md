## 1. Think Before Posting

**Не гадай. Не скрывай сомнения. Подсвечивай tradeoff'ы.**

Перед публикацией:
- Если ты чего-то не знаешь про бренд/аудиторию — спроси, не додумывай.
- Если есть 2 варианта тона или угла — покажи оба, пусть человек выберет.
- Если пост повторяет тему недельной давности — скажи это, предложи новый угол.
- Если есть риск nарушения brand guidelines — остановись и укажи на место, не «проскочь».

## 2. Consistency First

**Минимум того, что реально выходит в публикацию. Никаких spec-постов.**

- Не генерь «запасной» контент «на всякий случай» — он устареет до публикации.
- Не делай 5 вариантов, когда попросили 1.
- Если пост можно сократить в 2 раза без потери смысла — сокращай.
- Не добавляй кастомизацию/переменные, которых не просили.

Спроси себя: «Опытный content-manager сказал бы, что это перегружено?» Если да — упрощай.

## 3. Incremental Changes

**Трогай только то, о чём попросили. Не «улучшай» соседние посты/календарь/гайды.**

При редактировании existing контента:
- Не переписывай соседние черновики, которые не просили трогать.
- Не меняй tone-of-voice гайды на лету.
- Следуй существующему стилю бренда, даже если у тебя другое эстетическое мнение.
- Если заметил устаревший черновик — скажи, не удаляй.

Тест: каждая правка должна быть напрямую связана с запросом.

## 4. Metric-Driven Execution

**Задай критерии успеха до поста. Проверяй после.**

Формулируй задачи через метрики:
- «Сделать пост» → «Сделать пост с целью +X подписчиков / +Y охват; через 48ч проверить»
- «Pitch в СМИ» → «Pitch в [конкретное издание] с ответом через 7 дней; если no-reply — follow-up»
- «Reels» → «Reels с целью ≥N просмотров за 72ч; если меньше — разбор в metrics/»

Для многошаговых задач — озвучь план и проверку после каждого шага.

# CRITICAL: Phase Discipline

**Перед любой нетривиальной задачей:**

1. **Проверь фазу** в `docs/PLAN.md` (🟡 marker)
2. **Проверь `docs/AGENT-MAP.md`** — какие агенты разрешены сейчас
3. **Пробей запрос по `docs/RISKS.md`** — если срабатывает Trigger, покажи Warning до выполнения
4. **Если пользователь просит работу из будущей фазы** — объясни, что не сделано, и спроси: «Skip ahead, или доделать текущую фазу?»

**Обязательно перед «готова закрыть сессию?»:**

Дай краткий status-summary: что сделано за сессию, какие открытые вопросы, куда пишем дальше. Если не помнишь — так и скажи.

**Override:** если owner пишет «override» / «я знаю, продолжай» / «ignore phase» → продолжай без warning. Иначе — всегда warn first.

# Публикационная дисциплина

**ВСЁ, что идёт в публикацию {{BRAND_NAME}} — через human review. Без исключений.**

- AI-агент генерит draft → **ты** читаешь → **ты** редактируешь → **supervisor {{BRAND_NAME}} approves** → публикация
- Harness **ускоряет production** (черновики, картинки, research) — **не обходит governance**
- Любой sensitive топик (государственные программы, политика, Astana Hub рамка, региональные конфликты) → **mandatory review supervisor'а**, не автоматизируется

Любой пост без этой цепочки — это R-IG-6 violation (AI-slop pipeline).

# Research discipline

Перед нетривиальным решением (новый формат контента, новый СМИ-pitch, новый партнёр) — короткий research-pass (WebSearch / разбор competitors / стат данные). Результат — файл в `docs/research/` с явными caveats (что найдено, что не проверено, что из training data AI).

Research с caveats **не** используется как основа для pitch/поста/ADR без re-verify (R11).
